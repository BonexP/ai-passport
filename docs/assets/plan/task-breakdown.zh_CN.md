# 任务拆解

仅规划，尚无应用代码。本文件把 `project-plan.md` 里的分期拆成可验证的原子任务，
每个任务能在独立主题分支上完成并单独评审。

## 1. 每个任务都适用的规则

- 一个任务一个主题分支，从 `feature/my-custom` 切出，用 `--no-ff` 合回。
- 纯逻辑（状态机、调度、布局计算、解析决策）与 ESP-IDF、LVGL 解耦，以便主机测试覆盖。
  加了这类逻辑却没有主机测试的任务算未完成。
- 每次提交前 `./tools/validate.sh --static` 必须通过。
- 交付报告四行分开：Build、Host tests、Device tests、Unverified。
- 仍待定的具体数字（heap 水位、轮询间隔）在任务落地时记录，不预先猜。

## 3. P1：Wi-Fi profile 管理器

| 编号 | 任务 | 验收 |
| --- | --- | --- |
| P1.1 | 定义 profile 记录与 NVS schema：名称、SSID、密码、last_ok_time、active 索引 | Schema 写在头文件注释里；用桩键值存储在主机上做往返测试 |
| P1.2 | profile 存储模块，可主机测试，逻辑层不调 ESP-IDF | 增、改、删、列、选活跃五项都有主机测试 |
| P1.3 | 开机连接状态机：先试活跃项，失败按列表遍历并设单条超时，全失败进配网态 | 主机测试覆盖全部成功、中途成功、全部失败、超时四条路径 |
| P1.4 | 断线处理：重跑整个遍历，而不是只重试上一个 SSID | 转移有主机测试；真机行为在实测前记为 Unverified |
| P1.5 | 把 Wi-Fi worker 任务接到真实 ESP-IDF API | 构建通过；记录运行时的 free heap 与最大连续块 |
| P1.6 | 配网路径决策（参考 `demo/blufi-provisioning` 的 BLE 模式） | 决策落文档；实现作为独立任务单独评审 |
| P1.7 | 状态页 UI，重新设计而非照搬 demo | 交付报告里说明自有布局与按键交互；屏幕效果在看到真机前记为 Unverified |

说明：P1.3 的状态机是上游规则最希望放在主机测试下的部分。P1.6 的配网刻意单独拆出，
因为它引入 BLE 栈和"两栈永不同存"的约束。

## 8. 建议顺序

先跑 P0 的固件构建，然后 P1.1 到 P1.5 作为一个纵向切片（存储、状态机、worker），
接着 P2.1 与 P2.2（共用客户端与解析器），再 P2.3 与 P2.4，然后 P3，
P1.6 与 P1.7 可以并行放在 P2 阶段之后，因为配网和状态页都受益于可用的网络路径，
最后做 P4。

## 9. 可移植性任务（条件触发）

只有当 Windows 主机必须原生跑全套门禁时才需要。在那之前，按 `development-environment.md`
第 8 节：Windows 用原生构建与烧录，门禁交给 WSL2 或 CI。

| 编号 | 任务 | 验收 |
| --- | --- | --- |
| PT.1 | `validate.sh` 检测主机编译器缺失，给出清晰提示而不是难懂的链接错误 | 用 `CC=/nonexistent` 在 Linux 上模拟；提示信息明确说出编译器要求 |
| PT.2 | Windows 上接受已安装的 `actionlint`，不强行调安装脚本 | 已部分支持 `ACTIONLINT_BIN`；补上文档路径与打印修复办法的检查 |
| PT.3 | 用可移植复制替换 `install -m 0644` | 在没有 GNU `install` 的环境里门禁仍通过 |
| PT.4 | 增加 `.gitattributes`，把 `*.sh` 与文本文件固定为 LF | Windows 全新 checkout 工作树为 LF；门禁脚本不再报 `/usr/bin/env` 错误 |

PT.4 便宜且能消掉一整类难查的故障，值得在 Windows 成为主力平台之前就做。
PT.1 到 PT.3 在真正需要 Windows 原生门禁之前都是浪费。
